# 检查点

检查点是 Box 数据的副本。你可以从检查点派生新 Box，或将 Box 回滚到某个检查点。

检查点包含 Box 的 `/workspace` 文件夹和 home 文件夹。模板只包含系统文件，因此检查点是保存工作的方式。

检查点可在控制台中使用，也可通过 [REST API（英文）](../../reference/api.md) 使用。[MCP（英文）](../../reference/mcp.md) 的存储工具集同样可以导出、导入和设置检查点的计划，仅限所有者。命令行工具不管理检查点。

检查点不是整台服务器的备份。它们存放在拍摄时 Box 所在的宿主机上，Box 迁移后检查点仍留在原处。有多台宿主机时，检查点的行会标明其所在宿主机。回滚使用 Box 所在宿主机上的检查点，因此要回滚到另一台宿主机上的检查点，请先把 Box 迁移到那台宿主机。对不能丢失的数据请保留宿主机外的副本。可以[导出](#导出与导入)检查点，得到便于携带的副本，也可以把包推送到[异地目标](#异地目标)。若要备份整台服务器，请见[备份](../admin/backups.md)。

## 创建检查点

1. 打开 Box，点击**设置**，再点击**检查点**。
2. 点击**创建检查点**。
3. 在**标签**中输入短名称。留空则使用 Box 名称。
4. 在**一致性**下，选择复制文件时如何对待 Box：

   | 选项 | 行为 |
   |---|---|
   | **运行中** | Box 继续运行时进行复制。这是最快的方式。复制结果为崩溃一致。 |
   | **暂停** | 复制期间暂停运行中的 Box，然后恢复。复制期间文件不会变化。 |
   | **停止** | 复制期间停止 Box，然后再次启动。 |

   已停止或休眠的 Box 无论选哪项，都按当前状态复制。

5. 若要包含系统层，勾选**包含系统层**。这会保存 Box 已安装的软件，派生时会带上它们。耗时更长，占用更多空间。
6. 点击**创建检查点**。

检查点就绪后会出现在列表中。在**任务**面板中查看进度。

宿主机磁盘剩余空间低于下限时，MiniBox 会拒绝你手动创建的检查点、由检查点创建 Box、回滚、会先拍摄[安全检查点](#安全检查点)的重建，以及会保留副本到[回收站](#回收站)的删除。这些请求都会立即返回 `507`（`insufficient_storage`）。定时检查点则被跳过。参见[用量、上限与剩余空间](volumes-and-storage.md#用量上限与剩余空间)。

## 检查点列表

列表显示每个检查点的**拍摄时间**、**标签**、**类型**和**内容**。类型包括：

- **手动**：你拍摄的检查点。
- **自动**：MiniBox 拍摄的检查点。MiniBox 在每次回滚前、重建 Box 前以及挂载或卸载卷前，会拍摄一个[安全检查点](#安全检查点)；设置了[计划](#定时检查点)时也会按计划拍摄。
- **置顶**：你置顶的检查点。
- **旧版快照**：检查点功能出现之前的快照。可以派生或删除，但不能回滚到它。

## 派生检查点

派生会从检查点创建新 Box。来源 Box 不会改变。

1. 在该检查点行点击**派生**。
2. 在**新 Box 名称**中输入新 Box 的名称。
3. 若要复制 home 文件夹，勾选**复制 home**。默认关闭，因为 home 文件夹可能包含凭据等敏感文件。
4. 点击**派生**。

## 回滚到检查点

回滚会用检查点中的数据替换 Box 的当前数据。

1. 在该检查点行点击**回滚**。
2. 阅读对话框。其中列出**将被替换的卷**、**保持不变**和**将丢失**（容器中已更改的文件）。
3. 点击**回滚**。

在有任何更改之前，MiniBox 会为当前数据拍摄一个安全检查点。然后 Box 会用恢复的数据重建。

回滚后旧卷会保留，以便你决定如何处理。Box 的**设置**中**检查点**一组会显示**旧卷仍保留**，并提供两个按钮：

- **确认并清理**会删除旧卷。
- **撤销回滚**会再次挂载旧卷。回滚之后写入的内容都会丢失。

## 安全检查点

MiniBox 重建 Box 之前，会先拍摄该 Box 数据的安全检查点，这样重建出错时还能恢复数据。这包括在 Box 页点击**重建**、修改 Box 的模板、环境变量、挂载或安全档位引起的重建，以及挂载或卸载卷。安全检查点标签为**重建前**，并且是自动检查点。

默认会拍摄。若要跳过，请在重建预览中，或在确认挂载、卸载的对话框中，取消勾选**重建前先拍摄安全检查点**。REST API 用 `safetyCheckpoint: false` 达到同样的效果，MCP 工具 `rebuild_box`、`attach_volume` 和 `detach_volume` 也接受这个参数。

- 若重建失败且 MiniBox 恢复了 Box，安全检查点会被丢弃。
- 若无法把 Box 原样恢复，安全检查点会保留，错误信息会写明它的 id。可以从它派生新 Box 找回数据。
- 没有自有卷的 Box 没有需要保留的数据，因此不会为它拍摄检查点。
- 仓库达到上限时，与回滚一样，拒绝拍摄。宿主机磁盘剩余空间低于下限时，以 `507` 拒绝。

## 置顶与删除

- 点击**置顶**可保留检查点，即使自动清理运行也不会删除。点击**取消置顶**可再次允许清理。
- 点击**删除**可移除检查点。数据会从仓库中删除，且无法恢复。置顶的检查点须先取消置顶才能删除。

## 回收站

删除 Box 或卷时，MiniBox 会把它的数据副本保留在回收站中，在一段时间内可以将其恢复。在侧边栏打开**存储**，再点击**回收站**，即可看到各条记录，按删除时间从新到旧排列，并显示大小与每条记录的剩余时间。

删除时会保留：

- **Box**：它的 workspace 与 home 卷的数据，即它自有且检查点会包含的卷，默认为这两个。副本在 Box 被移除之前拍摄，无论你是否同时删除 Box 的卷，副本都会保留。缓存卷、共享的工具卷和独立卷不会保留。
- **卷**：它的数据。缓存卷与工具卷不保留任何内容。

若要恢复一条记录，点击**恢复**，并输入**名称**。该名称在所在宿主机上必须未被占用。Box 会作为新 Box 恢复，带回模板、数据、资源、安全档位与网络出站设置，但不会带回原 Box 的环境变量、启动命令、标签、TTL 与共享挂载。原 Box 使用 `none` 或 `proxy-only` 出站时，恢复后的 Box 会获得新的私有网络。见[网络出站](../admin/network-egress.md)。卷会作为新卷恢复。恢复以任务形式运行，完成后该记录才会移除，因此恢复失败时记录会保留在列表中。

点击**立即彻底删除**可立即移除一条记录及其数据，需先确认。删除后数据无法恢复。

记录保留 `TRASH_RETENTION_DAYS` 天，默认 7 天，管理员可设为 1 至 365 天。每小时的清理会删除到期的记录。记录不计入[自动检查点的保留限制](#检查点保留多久)。

若要删除且不保留副本，在删除对话框中勾选**删除时不保留副本**。数据会立即删除，无法恢复。只有所有者，或持有 `trash:skip` 权限的令牌可以这样做。通过 REST API，对 `DELETE /api/boxes/{id}` 或 `DELETE /api/volumes/{id}` 传入 `skipTrash=true`。MCP 工具 `delete_box` 与 `delete_volume` 接受 `skipTrash: true`。

记录保存在检查点仓库中，因此也计入大小上限 `CHECKPOINT_CAPACITY_MB`。若一次删除会使仓库超过上限，MiniBox 会先清除最旧的记录。仍不够时，删除会被拒绝，消息中写明所需与已用的大小，且不会停止或删除任何东西。宿主机磁盘剩余空间低于下限时，保留副本的删除会以 `507` 拒绝。

记录不会出现在检查点列表中。每台宿主机各有自己的回收站，页面列出所有宿主机的记录，恢复与彻底删除都在记录所在的宿主机上执行。每次删除、恢复与彻底删除都会记入事件日志，分别为 `box.trashed` 或 `volume.trashed`、`trash.restored` 与 `trash.purged`。回收站仅限所有者使用。

命令行中，`minibox trash ls` 列出记录，`minibox trash restore <id>` 恢复一条（可加 `--name`、`--cpus` 与 `--memory`），`minibox trash purge <id>` 彻底删除一条。MCP 工具为 `list_trash`、`restore_trash` 与 `purge_trash`。

## 导出与导入

导出检查点会得到一个可移植的包，即单个 `.mbckpt` 文件。你可以将它保存在宿主机之外，也可以导入到本实例或另一台 MiniBox 实例。导出与导入仅限所有者。

导出检查点的步骤：

1. 在该检查点的行中点击**导出**。
2. 输入**口令**，并在**再次输入口令**中重复输入。口令长 12 至 1024 个字符，首尾不能有空格，也不能包含换行。
3. 点击**导出**。导出以任务形式运行。包准备好后，浏览器会下载它。

包中只有检查点的数据，并以口令封装，不含你在 MiniBox 中保存的密钥。MiniBox 不保存口令，因此没有它，包就无法打开，包括你自己也打不开。包会在本实例上保留一天，之后每小时的清理会将其删除。

有些检查点不能导出：拍摄于检查点功能出现之前的快照、不含卷数据的检查点，以及包含系统层的检查点（包目前不携带系统层）。若要导出最后一类，请先不含系统层重新拍摄。

导入包的步骤：

1. 在 Box 的**设置**中，于**检查点**一组点击**导入**。
2. 选择**包文件**（一个 `.mbckpt` 文件），并输入封装它时使用的**口令**。若本实例有多台宿主机，选择要导入到的**宿主机**。
3. 点击**导入**。导入以任务形式运行。完成后即可从该检查点派生新 Box。只有当前 Box 就是它原来所属的 Box 时，它才会出现在这一组的列表中，详见下文。

口令错误会导致导入失败，包会保留，直到过期前都可以再次尝试。若本实例上已存在相同 id 的检查点，则不会导入，该实例上的内容也不会改变。

导入的检查点保留来源 Box 的 id。只有本实例上存在同 id 的 Box 时，它才会出现在该 Box 的列表中；它始终会出现在 `GET /api/checkpoints` 中。没有系统层的检查点从其拍摄时的模板派生，因此导入的宿主机需要该模板的镜像。

包的大小受 `CHECKPOINT_PACKAGE_MAX_MB` 限制，默认为 2048 MB。超过上限的导出会以 `payload_too_large` 失败。通过 REST API 的操作方式：用 `POST /api/checkpoints/{id}/export` 导出，用 `POST /api/packages` 以 `application/octet-stream` 上传文件，然后用 `POST /api/packages/{id}/import` 导入。见 [API 参考（英文）](../../reference/api.md)。

## 异地目标

异地目标是本机之外的 S3 兼容存储桶或 SFTP 文件夹。目标列在**设置**的**异地目标**下。推送和拉取检查点包是 [REST API（英文）](../../reference/api.md) 和 [MCP（英文）](../../reference/mcp.md) 存储工具集中仅限所有者的操作，每项都以任务形式运行。

请在导出的包过期之前推送它，过期时间为导出后 24 小时。从目标拉取的包可以按上文方法导入，但须在拉取后 24 小时内完成。添加目标的方法见[备份](../admin/backups.md#异地目标)。

## 定时检查点

Box 可以按计划拍摄检查点：每隔数小时，或每天在你选择的时间拍摄。计划默认关闭，未设置计划的 Box 与之前的行为相同。

设置计划：打开 Box 的**设置**，进入**检查点**，在**计划**中点击**设置计划**：

1. 在**时间方式**下，选择**每隔数小时**并输入**小时数**（1 至 720）；或选择**每天一次**并输入**时间**，如 `02:30`。时间按浏览器所在的时区计算，对话框里会标出时区。
2. 点击**保存计划**。

该组随后显示计划，如 `每天 03:00（Asia/Shanghai）`，以及按本地时间显示、并标出时区的**下次运行**和**上次运行**。上次运行会说明是否拍摄了检查点，或为何跳过或失败。**修改计划**用于编辑计划，**关闭计划**用于移除它。关闭计划会保留已拍摄的检查点。

计划检查点以**运行中**的方式拍摄，即 Box 继续运行时复制。它不置顶，并计为自动检查点，因此保留策略保留或删除它的方式，与回滚前由 MiniBox 拍摄的检查点相同。

MiniBox 从不为计划唤醒或启动 Box。已停止或休眠的 Box 会被跳过；计划检查点也不算作活动，不会让空闲的 Box 无法休眠。Box 迁移到其他宿主机后计划保留，下次运行在新宿主机上进行。仓库达到上限，或宿主机磁盘剩余空间低于下限时，同样会跳过，直到腾出空间。若 Box 已被删除，其计划会被移除。运行失败会记录错误。宿主机离线时，其计划会等待它恢复。

计划每分钟检查一次，保存在本实例上，重启后仍然有效。服务器停机期间到期的运行，会在服务器启动后执行一次，最迟约一分钟。每隔数小时的计划沿用原定时间，因此延迟的一次不会推迟之后的运行。每天一次的计划在下一个设定时间运行，夏令时开始或结束时仍按所在时区的钟点运行；被跳过的钟点推迟一小时运行，重复出现的钟点只运行一次。

通过 REST API，`PUT /api/boxes/{id}/checkpoint-schedule` 设置计划，同一路径上的 `DELETE` 移除计划。每天一次的计划可带 `timezone`（IANA 时区名，如 `Asia/Shanghai`），不带时按 UTC 计算，不接受 `+08:00` 这类偏移。若服务器不再识别已保存的时区，计划会暂按 UTC 运行，响应带 `timezoneUnknown: true`，该组会提示重新设置。MCP 的存储工具集也为所有者提供相同的操作。

## 检查点保留多久

- 手动和置顶的检查点会保留，直到你删除它们。
- 每个 Box 会保留自动检查点。计划检查点与安全检查点也属于自动检查点。MiniBox 保留最新的 20 个，并删除超过 30 天的旧检查点。管理员可以更改这些限制。见 [配置（英文）](../../reference/configuration.md)。
- 回收站的记录不是检查点，各自按其保留期保留，见[回收站](#回收站)。
- 管理员也可为所有检查点设置大小上限。达到上限时，MiniBox 不会拍摄新的自动检查点。出于同样原因，回滚以及会先拍摄安全检查点的重建也会被拒绝。回收站同样计入这一上限：删除保留副本时，会先清除最旧的记录，仍不够时才会拒绝。
