# 卷与存储

卷是存放文件的位置。卷与 Box 分离。一个 Box 使用零个或多个卷。只要卷还在，Box 停止、重建或删除后其中的文件仍会保留。

在侧栏点击 **存储**，在 **卷** 标签页查看卷和存储池。

## 卷角色

新 Box 默认获得四个卷：

| 角色 | 默认池 | 挂载于 | 模式 |
|---|---|---|---|
| **工作区** | 默认池 | `/workspace` | 读写 |
| **主目录** | 默认池 | `/home/dev` | 读写。视为敏感数据，可能存放凭据。 |
| **工具** | 默认池 | `/opt/minibox/tools` | 只读。每个池一个共享卷存放已安装工具。 |
| **缓存** | 本地池 | `/home/dev/.cache` | 读写。不包含在检查点和回收站中。 |

要使用不同卷，在创建对话框中点击 **自定义**。Box 仅挂载你列出的卷。要为已有 Box 添加卷，在其 Box 页面上挂载。

## 存储池

存储池是 MiniBox 创建卷的位置。有三种：

- **本地**池：卷在 Docker 宿主机磁盘上。该池始终存在，且为 cache 的默认池。
- **NFS** 池：卷在 NFS 服务器（例如 NAS）上。参见 [NFS 与 NAS 存储](nfs.md)。
- **路径**池：卷在你自行挂载到宿主机的文件夹中。

要添加 NFS 池，点击 **添加 NFS**。要添加路径池，点击 **添加路径**。点击 **保存存储池** 保存更改。

池表格对可用池显示 **可达**，对不可用池显示 **存储不可达**。还会显示剩余空间。

其中一个池为默认池。要更改默认池，在池对话框中点击 **设为默认池**，或在其行上使用 **默认** 设置。

仍包含卷的存储池无法移除。

## 创建与挂载卷

- 要创建卷，点击 **创建卷** 并选择存储池。该卷是独立的，即不绑定到某个 Box。
- 要将卷挂载到 Box，打开 Box 页面，使用 **挂载**。挂载卷属于更改 Box 的挂载，因此会先暂存，等应用暂存变更时才重建 Box。
- 要卸载卷，点击 **卸载**。卸载同样会暂存，该行会标上**待卸载**，直到你应用更改或点击**撤销**。

应用暂存变更前会先为 Box 拍摄[安全检查点](checkpoints.md#安全检查点)，除非你在确认对话框中取消勾选**重建前先拍摄安全检查点**。

更改 Box 的挂载会重建它。Box 保留名称和卷。可写层和运行中的进程会丢失。见[暂存更改并重建](boxes.md#暂存更改并重建)。

## 读写与只读

- **读写**挂载允许 Box 修改文件。
- **只读**挂载仅允许 Box 读取文件。

同一卷可被多个 Box 挂载。在第二个 Box 中以读写方式挂载卷时，控制台会要求确认。Docker 不会在 Box 之间锁定文件，因此两个 Box 写入同一文件可能互相覆盖。

## 为卷创建快照

在卷上点击 **快照**，即可把它的数据保存为一个检查点。

- **独立**卷直接为它本身创建快照，无论有没有 Box 挂载它。该检查点记录不含任何 Box，只包含这一个卷。**检查点** 标签页把它按卷名分组，并显示 **卷** 徽标，行内的**内容**一栏也会写出卷名。挂载该卷的 Box 在复制期间照常运行。
- Box **自有**的卷跟随它的所属 Box，所以它的 **快照** 按钮会为该 Box 拍摄检查点。该检查点总会包含该 Box 的工作区与主目录卷。

这类快照是手动检查点，因此[保留策略](checkpoints.md#检查点列表)不会自行删除它，也可以像其他检查点一样置顶与删除。它不含 Box 的设置，因此不能派生成 Box，也不能导出、复制或回滚到它：这些按钮不可用，接口也会带着原因拒绝。若要把 Box 的设置与数据一起保存，请改为拍摄该 Box 的检查点。

缓存卷与共享工具卷永远不会进入检查点，因此它们的 **快照** 按钮不可用。引擎已经丢失的卷也无法创建快照，因为复制只会把它重新创建成空卷。

命令行同样可以为卷创建快照：`minibox volume snapshot <id|name> [--label TEXT] [--pin]`，它会打印检查点的 id。

## 删除卷

在卷上点击 **删除**。MiniBox 不会删除仍被 Box 挂载的卷。

删除卷时，MiniBox 会把它的数据副本保留在[回收站](checkpoints.md#回收站)中，保留 `TRASH_RETENTION_DAYS` 天，默认 7 天。在**存储**中的**回收站**恢复对应记录，即可得到一个新卷。缓存卷与工具卷不保留任何内容。若要删除且不保留副本，请勾选**删除时不保留副本**。只有所有者，或持有 `trash:skip` 权限的令牌可以这样做。

删除 Box 时，你也可以删除该 Box 拥有的卷。参见 [删除 Box](boxes.md#删除-box)。

## 引擎丢失卷时

MiniBox 记录每个卷，数据则保存在引擎中。若引擎丢失了 MiniBox 仍有记录的卷，**卷** 页会在该卷上显示 **引擎中的卷缺失**。

共享的 **工具** 卷会自动重建。在创建、启动或重建 Box，把 Box 迁移到某台宿主机，安装或列出工具，以及 MiniBox 启动时，MiniBox 都会以同一名称重新创建工具卷。活动列表中会显示 **重新创建卷**。本地池上的卷会以空卷返回，卷中原有的工具已经丢失，因此它们会显示为未安装。要重新安装，请在 Box 的 **工具** 标签页点击 **补装缺失**。NFS 或路径池上的卷复用共享上的同一目录，其中的工具仍然保留。

工作区、主目录和缓存卷保存着你的数据，因此 MiniBox 不会重建它们。挂载其中之一的 Box 在引擎恢复该卷之前无法启动。若不再需要这些数据，请删除该 Box 并保留其卷，然后删除该卷。删除引擎已丢失的卷时不保留副本，因为引擎中已没有这些数据。

删除 Box 并保留其卷时，这些卷会显示 **所属 Box 已删除**。数据仍然保留。不再需要某个卷时，删除它即可释放空间。仍被 Box 挂载的卷不会被删除。

## 批量删除卷与清理孤立卷

在**存储**的**卷**标签页中勾选要删除的卷。表头的复选框会选中搜索结果中的全部卷。仍被 Box 挂载的卷与共享的工具卷不能选中。点击**删除所选**，确认前对话框会说明每个卷将如何处理。对话框中的**删除时不保留副本**对整批选中的卷生效。缓存卷不保留副本，删除后无法恢复。MiniBox 在删除每个卷时会再次检查：期间开始被 Box 或容器使用的卷、共享的工具卷与 MiniBox 的系统卷都不会被删除。

**清理孤立卷**列出 MiniBox 创建、且没有任何 Box 或容器使用的卷：没有 Box 配置引用或拥有它们，也没有容器挂载它们。例如已删除 Box 后遗留的卷，就是孤立卷。对话框会显示每个孤立卷的大小、上次使用时间与原 Box。共享的工具卷、MiniBox 的内部卷，以及创建或最近 5 分钟内使用过的卷，从不列出。多宿主机时，离线或出错的宿主机会被跳过，对话框会说明。确认后只删除对话框列出的卷，删除前会逐个再次检查，已不再是孤立卷的会保留并报告。孤立卷的数据会保留到回收站，缓存卷除外，删除后无法恢复。只有所有者可以清理孤立卷。

每次删除都会记入活动。命令行使用 `minibox volume delete` 与 `minibox volume prune`，参见 [CLI 参考（英文）](../../reference/cli.md#volumes)。

## 用量、上限与剩余空间

MiniBox 默认每 10 分钟统计一次每个卷的用量。你可以为每个卷设置软上限与硬上限，宿主机还保留一个剩余空间下限。**软告警是尽力而为，不是配额。** 它能让你及早发现卷在增长，但不会阻止卷超过软上限。

### 用量如何统计

- 本地池或路径池中的卷，用 `du` 统计其自身的目录树，结果即为该卷的大小。
- NFS 池中的卷，用 `df` 统计池的根目录。结果是整个共享的用量，因此同一池中各卷显示的数值相同，控制台会将其标注为整个共享的用量。MiniBox 从不遍历共享中的目录。
- 每次统计都有各自的截止时间：卷的目录树为 2 分钟，NFS 共享为 30 秒。超时无响应的挂载会记为一次失败的采样并注明原因，该卷保留上一次成功的数值。其他卷仍按各自的计划统计。
- 每台宿主机同时最多统计 4 个卷，卷很多时不会一次为每个卷都启动辅助容器。
- 趋势保留最近 24 次采样。重启会清空趋势，但最后一次的数值会保留。
- 采样间隔由 `VOLUME_USAGE_INTERVAL_SEC` 设置，范围为 60 到 86400 秒。参见[配置（英文）](../../reference/configuration.md#volumes-and-storage)。

要立即统计某个卷，在 **存储** 的 **卷** 标签页点击 **统计**，或调用 `POST /api/volumes/{id}/usage`。新数值立即用于判断能否启动 Box；告警与停止动作由后台采样在下一轮执行。

### 软上限与硬上限

在卷的行中点击 **上限** 设置其上限。上限以 GB 为单位，留空表示无上限。软上限不能高于硬上限。也可以用 `PUT /api/volumes/{id}/limits`（以字节为单位）或 MCP 工具 `set_volume_limits` 设置，仅所有者可以操作。

| 达到的上限 | MiniBox 的行为 |
|---|---|
| **软上限** | 记录 `volume.usage_high` 事件，通知渠道可以发送该事件，并在 **卷** 标签页高亮该卷。每次越过软上限记录一次；只有降到软上限以下后再次越过，才会再次记录。 |
| **硬上限**，动作为 **仅警告**（默认） | 记录 `volume.usage_limit` 事件并发送通知。Box 继续运行。 |
| **硬上限**，动作为 **停止挂载它的 Box** | 同上，并且停止挂载该卷的每个运行中的 Box。被停止的 Box 保持停止，其页面会显示原因 **卷超过硬上限**。 |

- 事件与通知都会注明原因：上限、用量、动作，以及被停止的 Box。
- 默认为 **仅警告**，因为停止 Box 可能打断其工作。对于绝不能超过硬上限的卷，请选择 **停止挂载它的 Box**。
- 告警与停止动作在每次采样时判断，因此两次采样之间 Box 可能写入超过上限的数据。新上限会立即保存，启动 Box 时立即按新上限检查。
- 卷超过硬上限且动作为 **停止挂载它的 Box** 时，MiniBox 拒绝创建、启动、重启或重建挂载该卷的 Box，也拒绝将该卷挂载到 Box 上。拒绝的错误码为 `volume_over_limit`（409）。提高或取消硬上限，或释放卷中的空间，然后再启动 Box。
- **NFS 卷不能设置上限。** 其用量是整个共享的，对单个卷设置上限无法生效。这类卷的 **上限** 按钮不可用。参见 [NFS 与 NAS 存储](nfs.md#用量与配额)。

### 宿主机剩余空间

MiniBox 检查引擎存放数据的磁盘的剩余空间。剩余空间低于 `HOST_DISK_MIN_FREE_PERCENT`（默认 10%）时：

- MiniBox 记录 `host.disk_low` 事件并发送通知，每次进入低空间状态只发送一次。
- MiniBox 立即以 `507`（`insufficient_storage`）拒绝会创建卷或检查点的请求，包括：创建卷（含新建 Box 的默认卷，以及由检查点创建 Box 时的卷）；拍摄检查点（含回滚或重建前拍摄的安全检查点）；回滚；导入检查点；把 Box 迁移到该宿主机；以及会保留副本到[回收站](checkpoints.md#回收站)的删除。定时检查点则被跳过，显示为「宿主机磁盘可用空间不足」。

剩余空间恢复到下限以上后，这些拒绝即告结束。设置 `HOST_DISK_MIN_FREE_PERCENT=0` 可关闭此下限。若 MiniBox 无法读取磁盘，则不拒绝任何操作。

该下限只阻止新建卷和检查点，不会停止已在写入磁盘的 Box。

### 配额

上限不是配额。MiniBox 目前不设置文件系统配额，因此两次采样之间，卷的用量可能超过上限。文件系统配额（例如 XFS 项目配额，或本地池上的 btrfs、ZFS 配额）属于后续工作。对于 NFS 池，请在 NAS 导出上设置配额。参见 [NFS 与 NAS 存储](nfs.md#用量与配额)。

## 卷中的文件

即使没有任何 Box 在使用，你也可以用命令行工具读写卷中的文件：

```bash
minibox files ls my-volume --path /
minibox files read my-volume notes.txt
minibox files write my-volume notes.txt --content "hello"
```

全部 `minibox files` 命令见 [CLI 参考（英文）](../../reference/cli.md)。要在 Box 页面上浏览、上传与下载文件，参见[文件](files.md)。
