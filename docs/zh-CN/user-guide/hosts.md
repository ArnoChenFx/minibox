# 宿主机

宿主机是 MiniBox 可以在其上运行 Box 的 Docker 引擎。运行 MiniBox 的机器始终是宿主机 **local**。你可以添加其他 Docker 引擎，并在创建 Box 时选择宿主机。

每个 Box 都会记录其宿主机。你对 Box 做的所有操作都在该宿主机上执行。

## 标识与名称

每台宿主机有一个 **标识**（id）和一个 **名称**。标识是宿主机的键：所有接口调用、任务、事件、审计记录和命令行参数都用标识指名宿主机，没有任何地方按名称查找宿主机。名称只是给人看的标签，是控制台显示的那个，也是 MiniBox 写进提示与日志的那个。

两台宿主机不能共用同一个名称。添加宿主机、生成配对码以及 Agent 完成配对时，若名称已被另一台宿主机占用，MiniBox 会以 `409` 和键 `host_name_taken` 拒绝，并在其中指出占用该名称的宿主机。名称比较时先做 Unicode NFC 规范化，再去掉首尾空白且不区分大小写，因此 `Lab` 与 ` lab ` 是同一个名称。不填名称时以标识作为名称，这条回退同样要经过检查：已有宿主机叫 `lab` 时，标识为 `lab` 且未填名称的新宿主机会以 `host_name_taken_by_id` 拒绝，提示给它填一个名称。尚未使用的配对码同样占用它的名称，其他宿主机再要这个名称会以 `host_name_pending` 拒绝，并指出该配对码对应的宿主机。这条规则只为让控制台与日志不会出现分不清是哪台机器的条目，并不是数据模型的一部分——识别宿主机靠的是标识。

MiniBox 目前不提供宿主机改名，所以要让出一个名称，只能先移除占用它的宿主机。

## 连接宿主机的方式

| 端点 | MiniBox 如何连接 | 你需要准备的内容 |
|---|---|---|
| `unix:///var/run/docker.sock` | 本机上的套接字，或挂载进容器的套接字 | 无其他要求 |
| `tcp://host:2376` | 引擎的 TLS 端口，双向 mutual TLS | 为引擎证书签名的 CA，以及引擎信任的客户端证书与私钥。 |
| `ssh://user@host` | 经 SSH 转发的引擎 Docker 套接字。只需开放 SSH 端口。 | 能以该用户登录的 SSH 密钥。套接字为 `/var/run/docker.sock`，除非路径另有说明。 |
| 无，由 Agent 主动连入 | 宿主机上的 [Agent（英文）](../../reference/agent.md) 主动建立出站连接到 MiniBox，宿主机不开放任何端口。 | 宿主机上的 Docker，以及来自 **添加宿主机** 的配对命令。可在 NAT 与防火墙之后使用。 |

## 添加 Agent 宿主机

Agent 是一个小程序，运行在宿主机上的容器中，并主动连接 MiniBox。宿主机无需开放端口，也不需要证书或 SSH 密钥，因此 Agent 可在 NAT 与防火墙之后工作。宿主机需要 Docker，并且必须能够访问命令中指定的 MiniBox 地址。

1. 在侧栏点击 **设置**，打开 **宿主机** 部分，然后点击 **添加宿主机**。
2. 选择 **Agent（推荐）**，填写 **标识**，并可选填写 **名称**。名称只是标签，不能与其他宿主机重名；不填则用标识。
3. 点击 **生成配对命令**。MiniBox 会显示一个配对码和一条 `docker run` 命令，分别提供 bash 与 PowerShell 版本。
4. 在宿主机上运行该命令。Agent 用配对码换取自己的凭据，并保存在 `minibox-agent` 数据卷中，重启后会自动重连。
5. Agent 连接后，对话框会关闭。宿主机随后显示为在线，并显示 Agent 版本和最后联系时间。

命令里的 Agent 镜像使用与本 MiniBox 自身版本相同的标签，因此 Agent 讲的协议与控制台期望的一致；开发构建没有自己的镜像标签，会改用 `latest`，并在命令上方说明。请通过 https 配对：纯 http 下只有 Agent 的首次握手带签名，网络路径上的人可以读到配对码，并在之后注入命令。控制台不在 https 上时，对话框会给出警告。

配对码只能使用一次，10 分钟后过期。MiniBox 一收到配对码就会将其作废，因此若 Agent 丢失了响应、未能保存凭据，该配对码将不再有效。此时请移除 Agent 的容器，然后点击 **生成新的配对码**。配对码过期前也可以重新生成（例如关掉了对话框）：用同一个标识再生成一次即可，新配对码会替换旧的，旧配对码随即作废。只有首次启动需要配对码。关于启动参数、数据卷以及 Agent 允许的操作，见 [Agent（英文）](../../reference/agent.md)。

## 通过 Docker 地址添加宿主机

1. 在侧栏点击 **设置**，然后打开 **宿主机** 部分。
2. 点击 **添加宿主机**，并选择 **Docker 地址**。
3. 填写表单：
   - **标识**：小写字母、数字和连字符，以字母开头。
   - **名称**：便于你识别的名称，不能与其他宿主机重名。不填则用标识。
   - **端点**：上表中的一种形式。
   - 端点所需的凭据字段：`tcp://` 需要 **CA 证书（PEM）**、**客户端证书（PEM）** 和 **客户端私钥（PEM）**；`ssh://` 需要 **SSH 私钥（OpenSSH 格式，无口令）**。
4. 先点击 **测试连接**。MiniBox 会连接引擎，读取其版本与容量并显示结果。不会保存任何内容。
5. 点击 **添加宿主机**。

对于 SSH 宿主机，MiniBox 会显示以 `SHA256:` 开头的 SSH 主机密钥指纹。请与机器上的密钥核对，然后点击 **信任并添加**。仅在指纹一致时才添加该宿主机。

凭据保存在 MiniBox 宿主机上，控制台不会再次显示它们。

## 对所有宿主机的访问

有多台宿主机时，本控制台是进入全部宿主机的入口。Docker 引擎在其所在机器上拥有 root 权限，因此能登录本控制台的人都可以操作每台宿主机。请妥善保管所有者密钥，并只给每个 [Agent 令牌](access-and-tokens.md)它需要的宿主机。除本机外还有其他宿主机时，**设置** 页会显示此提醒。

## 在其他宿主机上创建 Box

在创建对话框中选择 **宿主机**。默认为 **local**。选择 **自动** 时由 MiniBox 选择：它使用在线、持有模板镜像、且放置后剩余 CPU 与内存最多的宿主机。当持有官方模板的宿主机都没有余量时，官方模板会在尚未持有它的在线宿主机中，由剩余 CPU 与内存最多的一台构建。Agent 令牌只在其被授权的宿主机中选择。

在其他宿主机上的 Box 需要该宿主机 Docker 引擎上已有其模板镜像。若宿主机没有所选模板，MiniBox 会先把模板复制过去。创建对话框会显示复制的大小，复制以 **同步模板** 任务的形式运行，创建会等待复制完成。若要在不创建 Box 的情况下复制模板，请在 **库** 的 **模板** 标签页中，于模板卡片上点击 **同步到此宿主机**，或运行 `minibox template sync <ref> --host <id>`。

复制镜像的方式与迁移相同，因此目标引擎必须保留镜像 ID。见 [限制](#限制)。

## 按标签选择宿主机

宿主机可以带标签，创建 Box 时可以要求 **自动** 只在带这些标签的宿主机中选择。这样，一个控制面里型号不同的机器就能说清 Box 该放在哪里：一台有 GPU，一台磁盘更大，一台是另一种架构。

在 **设置** 的 **宿主机** 里给宿主机加标签，也可以通过 API 或命令行：

```bash
minibox host labels set lab --label gpu=true --label org/arch=amd64
minibox host labels get lab
```

`PATCH /api/hosts/{id}` 加 `{ "labels": { "gpu": "true" } }` 效果相同，传空对象则清空标签。`POST /api/hosts` 在添加宿主机时可以直接带 `labels`。键为小写，可以用一个斜杠表示命名空间，如 `org/arch`；值为单行、最多 256 个字符，可以为空。一台宿主机最多 32 个标签。

本机宿主机也能带标签，来源有两处：

- `.env` 里的 `HOST_LABELS`，例如 `HOST_LABELS=gpu,arch=amd64`，在启动时设置。MiniBox 会把它们写进 `hosts.json` 中 id 为 `local` 的记录，所以标签最终存在这个文件里。
- `PATCH /api/hosts/local`，或 `minibox host labels set local`，随时可以改。已经有标签的本机宿主机在下次启动时会保留它们，因此旧的 `.env` 不会覆盖你在控制台里做的修改。

要按标签放置 Box，宿主机选 **自动**，并给出标签。API 里这个字段是 `hostLabels`，命令行上每个标签一个 `--host-label`：

```bash
minibox box create trainer --host auto --host-label gpu=true --host-label org/arch=amd64
```

```json
{ "name": "trainer", "cpus": 4, "memoryMb": 8192, "host": "auto", "hostLabels": { "gpu": "true" } }
```

规则：

- 只考虑在线、并且带有**全部**这些标签的宿主机，每个值都必须完全一致。`--host-label gpu` 要求名为 `gpu`、值为空的标签。
- **自动** 的其余规则不变。在带标签的宿主机中，持有模板的排在未持有模板的前面，其中剩余空间最多的胜出；只有所有者的官方模板才可以在未持有它的宿主机上构建。
- 没有这些标签的宿主机永远不会成为候选，无论它有多少余量；本来会落到它上面的创建会被拒绝。
- 若没有任何在线宿主机带有这些标签，创建会以 `422` 和 `host_auto_no_label_match` 拒绝，并列出这些标签。不会创建任何东西。
- 标签只和 **自动** 一起使用。指定了宿主机又发标签会被 `host_labels_need_auto` 拒绝，因为指定宿主机时不做筛选。
- 不给 `hostLabels` 时，放置规则与标签功能出现之前完全一致。

## 容量

当有多个宿主机时，MiniBox 会统计每台宿主机上运行中 Box 预留的 CPU 与内存。新建、调整资源或迁移若会使预留超过宿主机容量，会被拒绝。`HOST_OVERCOMMIT` 可放宽这一限制，最多为宿主机容量的 10 倍（见 [配置（英文）](../../reference/configuration.md)）。已停止的 Box 不占用预留。

若某台宿主机上运行中 Box 预留的 CPU 或内存超过「容量 × `HOST_OVERCOMMIT`」，概览的 **需要关注** 会列出它，并带上已预定的总量与上限。调低 `HOST_OVERCOMMIT`，或宿主机重启后引擎报告的容量变小，都会让它出现在这里；预留重新装得下之后条目自动消失。宿主机未报告的数字不做检查。

## 把 Box 迁移到另一台宿主机

1. 打开 Box，点击 **迁移到宿主机**。有多个宿主机时才会显示该按钮。
2. 选择目标宿主机，点击 **预览**。预览会列出每个卷的处理方式、是否发送模板镜像，以及 Box 是否会在目标上启动。此时不会改变任何内容。
3. 点击 **迁移 Box**。迁移作为任务在任务面板中运行。

迁移会：

- 目标宿主机没有模板镜像时，把镜像发送过去，模板的构建记录也一并复制。
- 把本地卷复制到目标宿主机，复制期间运行中的 Box 会暂停。NFS 卷在目标上重新挂载，不复制。工具卷改用目标宿主机的共享工具卷。
- 在目标宿主机上创建 Box，原来在运行的会在那里启动。只有 Box 在目标上运行之后，才会从原宿主机移除。在此之前任何一步失败，迁移都会撤销，Box 留在原处。
- 保留 Box 的 ID、名称、卷、环境变量与历史。可写层、运行中的进程与 IP 地址会丢失，与重建相同。
- 检查点留在原宿主机，迁移后不会在新宿主机上恢复。预览会统计它们的数量。检查点包含卷数据，逐个复制会使迁移很慢，因此迁移不会带走它们。若要让某个检查点随 Box 保留，请先[复制](checkpoints.md#复制到其他宿主机)它到新宿主机，或[导出](checkpoints.md#导出与导入)它，再在新宿主机上导入。

只有所有者或 admin 令牌可以迁移 Box。使用绑定挂载卷，或其卷同时被其他 Box 挂载的 Box 不能迁移。

## 查看宿主机

**设置** 页面会列出每个宿主机及其 **状态**、**容量** 和上面的 **Box** 数量。当有多个宿主机时：

- 每个 Box 会标明其宿主机。
- 概览页会为每个宿主机显示一张卡片，包括状态、延迟、容器数，以及其 Box 预留与使用的 CPU 和内存。
- 顶栏可以按宿主机筛选列表。
- 离线的宿主机上的 Box 会显示为不可达，列表其余部分仍会加载。MiniBox 会在后台重新检查离线的宿主机，每次检查失败后等待更长的时间，最长约五分钟。
- Agent 宿主机会显示 Agent 的版本以及最后联系时间。若 Agent 使用的协议与当前 MiniBox 不同，宿主机会显示 **Agent 需要升级**。请拉取最新的 `minibox-agent` 镜像，并用同一个数据卷重新创建容器。

## 引擎存储占用

**设置 → 宿主机** 页面上，每个宿主机那一行下面还会列出它的引擎持有什么，按 `docker system df` 的口径统计：镜像、容器、卷与构建缓存各自占用多少字节，各有多少个、其中多少个在用，以及删掉不用部分能回收多少。读数在打开页面时读取，每台宿主机一次请求，不会拖住表格：表格先画出来，存储那一行随后填入。

这是引擎自己的统计，不是宿主机文件系统的容量。MiniBox 对卷与检查点执行的空闲空间下限用的是文件系统读数，两者可能不一致：宿主机剩余空间很多，但 Docker 自己的对象已经占掉大半磁盘，也是常见情形。

引擎没有报告的类别或数字显示为未知，而不是 0。不同版本的引擎报告的字段不同，例如引擎从未测量过某个卷的大小，就不会报告它的大小。

**Agent 宿主机没有这项读数。** Agent 只承载 Box 需要的操作，读取引擎自身的存储不在其中，所以它的那一行会直接说明。离线的宿主机、引擎在读取时限内没有应答的宿主机，或引擎拒绝读取的宿主机，都只在自己那一行说明原因，其他宿主机照常显示数字。MiniBox 不会自己清理镜像、容器或构建缓存：这项读数只告诉你现在有什么。

## 移除宿主机

点击该宿主机旁的 **移除** 并确认。仍持有 Box、卷或检查点的宿主机无法移除。**local** 宿主机无法移除。

移除宿主机时，还会删除 MiniBox 在那台机器上创建的共享工具卷（每个存储池一个，不算作该宿主机的卷）。机器有应答却拒绝删除时，移除会带着它的错误中止、什么都不改变，可以再试一次。机器离线时没有可以删除的途径，宿主机照样被移除，日志 `host.tools_volume_left` 会写明留在机器上的卷，需要时在那台机器上用 `docker volume rm` 删除。

Agent 宿主机只有 **移除** 按钮。移除时会先吊销它的 Agent：Agent 立即断开且无法再次连接，MiniBox 随后删除其记录。要再用这台机器，请用新的配对码和新的数据卷重新配对，见 [Agent 参考（英文）](../../reference/agent.md#remove-revoke-upgrade-and-re-pair)。移除不会删除机器上的任何容器，唯一会删除的卷是 MiniBox 在那里创建的共享工具卷（名为 `<前缀>-tools-<宿主机 id>`，每个存储池一个），只有 MiniBox 的 Box 会挂载它。Agent 的容器会在机器上空转。请在机器上使用 `docker rm -f` 停止并删除该容器。

宿主机仍持有 Box、卷或检查点、又需要立即切断其 Agent 时，请调用 `POST /api/hosts/{id}/revoke`。这个接口为此保留，已有脚本也照常可用。被吊销的宿主机会留在列表中并标记为 **已吊销**，直到你移除它。

## 限制

- 复制或迁移镜像要求目标引擎保留镜像 ID。Docker 的经典镜像存储满足此要求。containerd 镜像存储在加载镜像时会改变镜像 ID，因此 MiniBox 会以 `docker_error` 拒绝复制，并列出两个 ID。若 `docker info` 显示 `driver-type io.containerd.snapshotter.v1`，即表示该引擎使用 containerd 镜像存储。
- 每个宿主机各自保留检查点。要让另一台宿主机也有某个检查点，请[复制](checkpoints.md#复制到其他宿主机)它。副本是新检查点，原检查点留在原处。带系统层的检查点暂时不能复制。
- **自动** 只考虑已持有模板镜像的宿主机，除非所有者的官方模板可以在某台上构建。要限定它可用的宿主机，请给宿主机加标签并传 `hostLabels`；不传时它会考虑所有在线宿主机。
- Agent 宿主机暂不支持迁入或迁出 Box，因为 Agent 既不复制镜像，也不复制卷。因此有多台宿主机时，Agent 宿主机上的 Box **迁移到宿主机** 按钮不可用，原因写在悬停提示里，API 则返回 `501 move_agent_unsupported`。请直接在想要的位置创建 Box。Agent 宿主机暂不支持模板、快照与端口预览，**存为模板** 在那里同样不可用；也不能在其上创建带自助令牌的 Box，因为 Agent 无法写入令牌文件。
- 宿主机级别的 CPU 与内存占用仅对本机宿主机显示。远程宿主机显示其引擎上报的核心数与内存，以及其上 Box 的占用。
- 命令行工具的宿主机命令只读写标签：`minibox host labels get` 与 `minibox host labels set`。添加和移除宿主机请在控制台或通过 [REST API（英文）](../../reference/api.md) 完成，吊销宿主机请通过 REST API 完成。
- [Agent 令牌](access-and-tokens.md) 可以限制为特定宿主机。
