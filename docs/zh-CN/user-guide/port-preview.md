# 端口预览

端口预览让你打开运行在 Box 内的 Web 应用。应用经 MiniBox 呈现，因此你无需在宿主机上发布端口。

你必须已登录 MiniBox 才能打开预览。

## 打开预览

1. 在 Box 内启动 Web 服务器。例如，在 **终端** 选项卡中运行：

   ```bash
   python3 -m http.server 8000
   ```

2. 打开该 Box，点击 **端口** 选项卡。
3. 若端口未列出，点击 **刷新**。MiniBox 会扫描 Box 内正在监听的端口。
4. 点击该端口旁的 **打开**。

预览的地址取决于管理员如何设置 MiniBox。

- **路径模式**为默认设置。预览位于 MiniBox 地址之下：

  ```
  http://127.0.0.1:3920/box/<name>/<port>/
  ```

  将 `<name>` 替换为 Box 的名称或其 ID。例如：`http://127.0.0.1:3920/box/my-box/8000/`。

- **子域名模式**为每个预览提供独立的地址：

  ```
  https://<port>-<box>.<domain>/
  ```

  例如：`https://8000-my-box.minibox-preview.net/`。应用运行在 `/`。若 Box 名称仅由小写字母、数字和连字符组成，`<box>` 部分即为该名称，否则为 Box 的 ID。

在新标签页中打开预览。预览在沙箱中运行，因此无法读取你的 MiniBox 登录 cookie。在子域名模式下，预览还运行在自己的地址上，因此无法调用 MiniBox 的 API。

## 路径模式与浏览器隔离

路径模式下，预览与 MiniBox 共用同一地址。其隔离依赖浏览器的行为：预览在沙箱中运行，登录 cookie 为 `HttpOnly` 且 `SameSite=Strict`。对单一可信用户而言，这已经足够。若其他人可以访问 MiniBox，或某个 Box 运行着你并不完全信任的代码，请让管理员开启子域名模式。见 [子域名预览](../admin/preview-subdomains.md)。

## 手动添加端口

当端口未列出，或应用在打开选项卡之后才启动时使用。

1. 在 **端口** 选项卡上，点击 **添加端口**。
2. 输入端口号，并在对话框中点击 **添加端口**。

添加端口仅将其保存供预览使用。不会在宿主机上发布端口。

## 框架

在路径模式下，许多 Web 框架假定应用位于 `/`。请将应用的 base path 设为 `/box/<name>/<port>/`。例如在 Vite 中设置 `base`，或在 Next.js 中设置 `assetPrefix`。

未做此设置时，页面会从错误的地址加载脚本与样式。在子域名模式下，应用位于 `/`，无需设置 base path。

WebSocket 连接可经预览工作。Vite 的热模块替换使用 WebSocket，因此同样可用。

## 位于其他宿主机上的 Box

通过 SSH、双向 TLS 或 Unix 套接字连接的其他宿主机上的 Box，经该宿主机的引擎提供预览。预览地址与本机 Box 相同。MiniBox 会用 `python3` 在 Box 内启动一个小型中继，由中继连接 Box 回环地址上的端口。远程宿主机不开放任何端口。

Box 内需要 `python3` 位于路径中，基础模板已包含。缺少时预览返回 `502` 错误，并说明原因。HTTP 与 WebSocket 的工作方式与本机 Box 相同。访问休眠中的 Box 会将其唤醒，响应或 WebSocket 打开期间 Box 保持唤醒。

## 限制

- Agent 宿主机上的 Box 暂不支持端口预览。
- 不提供分享链接。请在已登录时从 **端口** 选项卡打开预览。在子域名模式下，预览地址不能直接打开。从 **端口** 选项卡打开后，该浏览器可在最长 8 小时内（或直到你退出登录）使用此预览。
- 重命名 Box 可能会改变其子域名地址。重命名之后预览将无法加载，请从 **端口** 选项卡重新打开。
- 在子域名模式下，一个预览中的页面不能改动另一个端口的预览，也不能向其打开 WebSocket。其自身页面工作如常。
- 预览在响应加载期间以及 WebSocket 打开期间会保持 Box 唤醒。见 [空闲休眠与 TTL](idle-sleep.md)。
