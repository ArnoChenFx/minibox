# 工具

工具是你安装到 Box 中的程序，例如 AI 编程 Agent、语言运行时和命令行实用程序。MiniBox 有工具目录。你也可以添加自己的工具。

先核对工具显示的依赖与 Box 模板。base 和 `node` 模板包含 Node.js 26，`python`、`go`、`minimal` 模板不包含 Node.js。Claude Code、Codex、OpenCode、Pi、Qoder 等 npm Agent 即使由工具写入器成功安装，其运行时仍需要 Box 内有 Node.js；请先在派生模板中补齐要求的运行时。把工具安装到共享工具卷，不会给所有 Box 镜像安装运行时。

## 创建 Box 时选择工具

在创建对话框中，**工具** 部分列出目录中的工具。勾选需要的工具。用 **搜索工具** 按名称、说明或分类筛选。

工具分为：

- **AI 编程代理**
- **语言与运行时**
- **终端与开发工具**
- **网络**

目录包括 Claude Code、OpenAI Codex CLI、OpenCode、Pi coding agent、fx agent、Antigravity CLI、Grok Build CLI、Qoder CLI、oh-my-pi、herdr、luvus、Bun、uv、Rust toolchain、Zig、GitHub CLI 和 Tailscale。

若勾选了工具，MiniBox 会在 Box 启动后安装它们。在 **任务** 面板中查看进度。

## 在 Box 中管理工具

打开 Box，点击 **设置**，再点击 **工具**。表格显示每个工具的 **期望版本** 与 **已安装** 状态。各分组默认展开：可点击分组标题折叠，搜索工具则会在所有分组中显示匹配项。

- **安装** 将目录工具加入共享 tools 卷和 Box 的工具列表。
- **升级** 将该卷上已安装工具刷新为目录当前版本。
- **卸载** 从共享 tools 卷和 Box 工具列表中移除工具。
- **补装缺失** 安装 Box 列表中仍显示为未安装的全部工具。

同一宿主机上的工具操作写入同一个共享 tools 卷，因此逐个进行。若在另一个操作进行时开始新的操作，它会进入队列：该工具与 **任务** 面板中的任务都显示 **排队中**，前面的操作完成后按开始的先后顺序执行。排队期间再次点击同一操作不会新增任务。要放弃排队中的操作，取消它的任务即可。

已在 Box 镜像或 home 卷中的工具会显示为已安装及版本号。MiniBox 不会改动它们。**升级** 和 **卸载** 仅适用于 MiniBox 安装的工具。

部分工具需要 root 和系统服务。MiniBox 从不运行这些工具。目录将它们标记为 **需要 root**。请自行在宿主机上安装。

工具写入共享 tools 卷，在各 Box 中以只读方式挂载。同一宿主机上使用同一存储池 tools 卷的每个 Box 共享各工具的程序文件。安装到一个 Box 的工具，对共享该卷的其他 Box 也可用。

若引擎丢失了共享 tools 卷，MiniBox 会重新创建它。本地池上的卷会以空卷返回，卷中原有的工具会显示为未安装。点击 **补装缺失** 即可重新安装。参见[卷与存储](volumes-and-storage.md#引擎丢失卷时)。

## Tailscale

Tailscale 将 Box 连接到你的 tailnet。从目录安装后：

1. 在 Box 的 **终端** 标签页运行 `minibox-tailscale up`。它会打印登录 URL。
2. 打开 URL，登录你的 tailnet。

请记住：

- Box 不会在 tailnet 上获得网络接口。监听 `localhost` 或 `0.0.0.0` 的程序可在 tailnet 上访问，具体取决于 tailnet 访问规则。
- 要从 Box 访问 tailnet 主机，使用 `localhost:1055` 上的 SOCKS5 和 HTTP 代理。设置 `ALL_PROXY=socks5h://localhost:1055`。HTTP 客户端将 `HTTP_PROXY` 和 `HTTPS_PROXY` 设为 `http://localhost:1055`。
- `ping` 不能用于 tailnet 主机。请改用 `minibox-tailscale ping`。
- Box 重启或从休眠唤醒后，再次运行 `minibox-tailscale up`。会复用已保存的登录。
- tailnet 流量不会唤醒休眠的 Box。
- 卸载 Tailscale 仅停止该 Box 中的守护进程。登录状态仍保留在 home 卷上。

## 自定义工具

只有 MiniBox 安装的所有者可以添加或修改自定义工具。Agent 令牌无法使用自定义工具。

1. 打开 Box，点击 **设置**，再点击 **工具**，然后点击 **自定义工具**。
2. 填写表单：
   - **标识**：小写字母、数字和连字符，以字母开头。
   - **名称**、**说明** 和 **分组**。
   - **来源**、**包名** 和 **命令名**。
   - **命令**：**安装**、**升级**、**卸载** 和 **检测**。**停止（可选）** 在卸载前停止工具正在运行的程序。
3. 点击 **保存**。

每条命令最多 16,000 个字符。**检测** 在工具存在时必须以代码 0 退出。

若标识与内置工具相同，勾选 **替换内置条目**。删除该自定义条目会恢复内置工具。

**删除** 仅移除自定义条目。已安装在共享 tools 卷上的工具仍会保持安装。

## 复制与粘贴 JSON

表格里每个工具都有一个复制按钮，就在安装、升级或卸载按钮旁边；按钮只显示图标，鼠标悬停的提示写着**复制 JSON**（窄窗口下文字会占掉旁边按钮需要的宽度）。它把这个工具的目录条目复制成 JSON，形状与服务器上 `catalog/` 目录里的文件一致：`id`、`name`、`description`、`category`、`source`、`package`、`bin`、`needsRoot`、`estimatedMb`、`requires`、`install`、`upgrade`、`uninstall`、`stop` 和 `detect`。`requires` 与 `stop` 只在工具设置了它们时才出现。安装状态不在其中，所以复制出来的是工具本身，而不是这个 Box 的状态。

内置工具没有编辑和删除按钮，这一点不变：它们的 JSON 只作只读复制，用来派生一个自己的工具。自定义工具那一行在 **编辑** 与 **删除** 旁边同样有这个复制按钮。

派生一个工具的步骤：

1. 点该工具那一行的复制按钮（提示写着**复制 JSON**）。提示条会确认已复制到剪贴板。浏览器拒绝时，MiniBox 仍会走旧的剪贴板通道；这条也失败时给出可读提示。
2. 点 **自定义工具**，在对话框里展开 **粘贴 JSON**，把文本粘贴进去。
3. 点 **填入表单**。表单会按描述填好，**标识** 会变成 `<id>-copy`，因为目录里已经有这个工具：粘贴是新增工具，而不是替换内置条目。`<id>-copy` 也被占用时依次变成 `-copy-2`、`-copy-3`，且始终不超过标识允许的 63 个字符。
4. 按需要修改，然后点 **保存**。

保存的仍然是表单，所以粘贴填进去的每一项都能先改。在**编辑**已有条目时粘贴，**标识** 与 **替换内置条目** 保持不变：标识就是正在编辑的那个文件名，不能改名。无法解析、或带有表单不认识字段的描述，会在 **粘贴 JSON** 折叠区里给出指明问题的提示，表单里已经填好的内容不会被清空。描述里没有 `category`、`source`、`needsRoot`、`estimatedMb`、`requires` 或 `stop` 时，采用与新建条目相同的默认值：`agents`、`npm`、不需要 root、50 MB，两个可选字段都留空。

复制出来的 JSON 也可以存成服务器上的 `DATA_DIR/tools.d/<id>.json` 文件，或原样发给 `PUT /api/tools/custom/<id>`。若描述里的标识是内置工具，那条接口需要 `overrideBuiltin: true`，因为它是替换内置条目而不是新增工具。
