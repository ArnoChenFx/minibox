# 终端与会话

每个 Box 在浏览器中有一个终端。终端以用户 `dev` 在 `/workspace` 文件夹中运行 shell。

终端工作在会话中进行。会话是 Box 内具名的 tmux 会话。关闭页面后会话继续运行，返回时会从离开处恢复。关闭会话或 Box 停止时会话结束。

## 打开终端

1. 打开 Box，点击 **终端** 标签页。
2. 若 Box 已停止，点击 **启动 Box**。

若 Box 处于休眠，终端会唤醒它。你手动停止的 Box 不会因终端而唤醒。参见[空闲休眠与 TTL](idle-sleep.md)。

## 在手机上输入

手机的软键盘没有 Esc、Ctrl、Tab 和方向键。屏幕宽度在 640 像素及以下时，终端底部会出现一条这些键的辅助键行，手机也能像桌面一样操作同样的程序。

- **Esc**、**Tab** 与四个方向键发出的字节与键盘上同名的键相同。
- **Ctrl** 是修饰键。按一次后它保持按下，显示为强调色，接下来输入的一个字符会以控制字符发出：先按 **Ctrl** 再按 `c` 就是 Ctrl-C，先按 **Ctrl** 再按 `[` 就是 Esc。发出这个字符后它自动复位，再按一次 **Ctrl** 则取消。
- **^C** 与 **^D** 直接发送 Ctrl-C 与 Ctrl-D，终端里最常用的就是这两个。

这些键发给屏幕上的会话，因此只在你可输入时有效：Agent 持有的会话会显示为灰色，接管后才能使用。按这些键不会收起软键盘，之后输入的字符仍进入终端。超过 640 像素时不显示这一行，因为桌面键盘本来就有这些键。

## 调整终端高度

桌面浏览器（窗口宽度大于 900 像素）上，终端按页面实际剩下的空间铺开，而不是固定 460 像素，所以默认情况下整块终端连同它下面的抓手都在窗口内，1080p 与 1440p 屏幕上原本留在终端下面的空白也变成终端的一部分。这块空间是面板在终端打开时、以及窗口每次变化时实测出来的：窗口高度，减去屏幕起点以上的部分，再减去屏幕下方页面画的东西（抓手、帮助行、页面底部内边距）。默认高度是 `clamp(460px, 实测空间, 980px)`：

- 1920×1080 的屏幕剩下 663 像素，终端就开到 663 像素，整页不用滚动就能放下。
- 1440×900 的窗口剩下 435 像素，终端就开到它一直以来的 460 像素，屏幕和抓手都落在窗口内。
- 1280×800 的窗口只剩 335 像素，连旧的 460 像素都放不下。这时终端仍开 460 像素，页面照常滚动，与改动前完全一致。

页面仍然照常上下滚动，没有变成不可滚动的应用式布局。

终端框底部有一道抓手（一条短横条），可以把它拖到你想要的高度：向下拖变高，向上拖变矮，范围从 240 像素到默认高度再加 120 像素。拖动可以让屏幕越过窗口下沿，这正是「想要比一屏更多行」时用的。抓手也能用键盘操作：

- 焦点在抓手上时，按 **↑** 每次变高 24 像素，按 **↓** 每次变矮 24 像素。
- **Home**、**End** 或 **Enter** 恢复默认高度，用鼠标**双击**抓手也一样。
- 用 **Tab** 可以把焦点移到抓手上，聚焦时有可见的轮廓；拖动不会抢走终端的输入焦点，拖完仍可直接在终端里输入。

调整时终端会立即按新的高度重算列数与行数（xterm 的 FitAddon），并把新的尺寸发给 Box 内的 tmux，所以会话里的程序看到的是新的窗口大小。

你调过的高度记在这台机器的浏览器本地（`localStorage`，键名 `minibox:termHeight:v1`），刷新页面、切换到别的 Box、切换到别的会话都会沿用，也不会发给服务端。窗口变小后放不下这个高度时，会夹到页面实际剩下的空间；窗口再变大就恢复你原来的高度。双击抓手或按 Home/End 会清掉这个记忆，终端重新跟随页面剩下的空间。

手机（640 像素及以下）上不显示抓手，终端高度仍是 `min(52vh, 340px)`，按键行、软键盘让位与滚动逻辑都不受影响；641–900 像素的窗口也保持原来的 460 像素。

## 新建会话

1. 在 **终端** 标签页，点击 **新建会话**。
2. **会话名称** 里已经填好了一个名称，可以直接点 **新建会话**（或按回车），也可以改成自己想要的名称。名称最多 32 个字母、数字、短横线和下划线。
3. 点击 **新建会话**。

对话框填好的名称是一串名字里下一个没被占用的：Box 还没有同名会话时是 `console`，之后是 `console-2`、`console-3`……。Box 首次打开终端时自动创建的会话就叫 `console`，所以已经打开过终端的 Box 会给出 `console-2`。因此连点两次新建不会给出同一个名称，名字也读起来像一组编号，而不是一串随机字符。

名称在对话框里就先检查，不会等到发出请求才发现问题。Box 已有的名称（不区分大小写）会在输入框下方直接提示，服务端会拒绝的名称（比如带空格或超过 32 个字符）同样当场标出。把输入框清空也会被拒绝：名称在这里选，空名称不会发给服务端。服务端仍会再检查一次名称格式，若被拒绝则以提示条显示原因。

会话名称用于再次找到该会话。**会话** 列表显示 Box 中的全部会话。每个会话都标明创建者：**你创建** 表示你在控制台中启动的会话，**Agent 创建** 表示 Agent 或其他通过 API 连接的客户端启动的会话。运行启动命令的会话 `minibox-init` 没有标记，因此同样显示 **Agent 创建**。

要结束会话，点击 **关闭会话** 并确认。会话中运行的程序会停止。

一个 Box 最多 16 个会话。每个会话同时最多打开 8 个终端。

## Agent 驱动的会话

AI Agent 可在 Box 中启动自己的会话。这些会话称为 Agent 会话。

- Agent 会话在控制台中以只读方式打开。**终端** 标签页显示 **Agent 操作中**，附注「Agent 操作时此会话只读。接管后即可输入。」
- 要在会话中输入，点击 **接管**。
- 要将会话交还给 Agent，点击 **交还 Agent**。

你接管的会话在你一段时间无输入后会自动交还给 Agent。管理员用 `SESSION_TAKEOVER_IDLE_SEC` 设置该时长。默认 300 秒。若时长为 `0`，会话会一直由你持有，直到你手动交还。

你自己启动的会话始终由你持有。需要 Agent 在其中输入时再交还给 Agent。

你持有会话期间，Agent 仍可读取其屏幕，但在你交还之前 Agent 的输入会被拒绝。

重启 MiniBox 会将每个会话恢复到初始控制状态：Agent 会话归 Agent，你启动的会话归你。

## 在概览中观察 Agent

**概览** 页的 **正在进行** 列出最近 10 分钟内 Agent 操作过的 Box。每一行显示 Box、操作者（访问令牌的名称，或 Box 内的 Agent）以及 Agent 最近执行的命令。命令仍在运行时，该行还会显示输出的最后 3 行。该行还会列出 Agent 最近使用的会话。

- **观察** 以只读方式打开该会话。
- **接管** 打开同一会话。概览不会替你接管。在 **终端** 标签页点击 **接管** 才能输入。

不属于任何会话的命令只有 **观察**。它会打开 Box 的 **活动** 标签页，命令列在那里。

每个会话都有自己的地址，地址以会话名称结尾。在列表中选择另一个会话时，地址随之改变，因此刷新页面或分享链接后仍会打开该会话。

## 在命令行中使用会话

```bash
minibox session ls my-box
minibox session start my-box build
minibox session read my-box build --lines 50
minibox session send my-box build --text "npm test"
minibox session send my-box build --key Enter
minibox session close my-box build
```

全部选项见 [CLI 参考（英文）](../../reference/cli.md)。
