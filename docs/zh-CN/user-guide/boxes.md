# Box

Box 是一个隔离的 Docker 容器，拥有独立的文件和进程。你的工作保存在其 `/workspace` 文件夹中，该文件夹保存在卷里。停止、重启或重建 Box 时，该文件夹会保留。

每个 Box 以用户 `dev`（用户 ID 1000）运行。在 Box 内，`sudo` 无需密码即可使用。Box 内的 root 可以更改该 Box 内的任何内容。若要更严格的 Box，创建时选择 `strict` 安全档位。见 [安全（英文）](../../admin/security.md)。

## 创建 Box

1. 在侧栏点击 **Box**，然后点击**创建 Box**。
2. 在**名称**中输入名称。须以字母或数字开头，只能使用字母、数字、点、下划线和连字符，且最多 63 个字符。在控制台中，Box 创建后不能更改名称。
3. 在**模板**中选择起始模板。默认为 **base**。见 [模板](templates.md)。
4. 在**规格**中选择预设：

   | 预设 | CPU | 内存 |
   |---|---|---|
   | **小型** | 2 核 | 4 GB |
   | **中型** | 4 核 | 8 GB |
   | **大型** | 8 核 | 16 GB |
   | **自定义** | 自行设置 | 自行设置 |

   使用**内存**可设置精确数值（MB），范围 128 到界面显示的上限。

5. 要让 Box 内的 Agent 拥有仅供该 Box 使用的令牌，勾选**为 Box 的 Agent 启用自助令牌**。默认关闭，从快照创建的 Box 不提供此选项。见 [Box 内的 Agent](agents.md#box-内的-agent)。
6. 若 MiniBox 有多台宿主机，选择 Box 运行的**宿主机**。见 [宿主机](hosts.md)。
7. 要更改安全档位，打开**高级**并选择档位。默认为 `standard`。同一区域还可以设置可选的**网络出站**，用于限制 Box 可以访问宿主机之外的哪些地址，以及可选的**启动命令**。见[网络出站](../admin/network-egress.md)与[启动命令](#启动命令)。
8. 要把 Git 代码仓库克隆进 `/workspace`，打开**克隆代码仓库到 /workspace**。见[克隆代码仓库](#克隆代码仓库)。
9. 要在 Box 中安装 Agent CLI 或其他工具，在**工具**下勾选。见 [工具](tools.md)。
10. 打开**卷：默认**，然后选择**默认**以挂载 workspace、home、cache 和 tools 卷，或选择**自定义**自行挑选卷。见 [卷与存储](volumes-and-storage.md)。
11. 要设置环境变量，打开**环境变量**。见 [环境变量与密钥](environment-and-secrets.md)。
12. 点击**创建并启动**。

Box 会出现在列表中并显示状态。打开它可查看详情。由 `devcontainer.json` 构建的模板创建的 Box，还会运行该模板的设置。参见 [devcontainer.json](templates.md#devcontainerjson)。

## 克隆代码仓库

新 Box 可以在 `/workspace` 中以一份 Git 代码仓库作为起点。在创建对话框中打开**克隆代码仓库到 /workspace**，并填写以下字段：

- **代码仓库地址** 是 HTTPS 或 SSH 地址，例如 `https://github.com/org/app.git` 或 `git@github.com:org/app.git`。不要把令牌或密码写进 HTTPS 地址。
- **分支** 可以是分支或标签名。留空则使用默认分支。
- **私有仓库的密钥** 指向一个密钥，其中保存 HTTPS 使用的令牌，或 SSH 使用的 base64 部署密钥。请先设置该密钥。参见[环境变量与密钥](environment-and-secrets.md)。

同样的字段在 API 中是 `repo` 对象；在命令行中是 `minibox box create` 的 `--repo`、`--branch` 和 `--secret` 选项；在 MCP 中是 `create_box` 工具的 `repo` 参数。参见 [REST API（英文）](../../reference/api.md)、[CLI 参考（英文）](../../reference/cli.md) 和 [MCP 工具（英文）](../../reference/mcp.md)。

克隆只在创建 Box 时运行一次：

- 克隆为浅克隆。工作区只获得分支的最新提交，不含历史。
- 先创建 Box，然后它的设置作为独立任务**设置 Box**运行。设置先克隆代码仓库，再转发端口，并运行模板设置的 `postCreateCommand`（如有）。在**任务**面板中查看进度。若克隆失败，Box 会保留，任务会说明原因。
- 启动、停止、重启和重建 Box 都不会再次克隆，也不会再次运行设置。参见 [Box 的设置](templates.md#box-的设置)。
- `/workspace` 必须可写。默认卷会为新 Box 提供空的工作区。若你选择**自定义**，并把一个已有文件的卷挂载到 `/workspace`，克隆会失败。

密钥的值只在克隆时读取。它永远不会写入 Box 或其镜像，任务日志中的克隆输出会把该值替换掉。若所选密钥未设置，创建会在任何内容生成之前被拒绝。关于克隆能访问的范围以及 SSH 主机密钥的校验方式，参见[安全（英文）](../../admin/security.md#template-builds-and-repository-clones)。

## 打开 Box

在列表中点击 Box 即可打开。Box 页面包含以下标签页：

| 标签页 | 内容 |
|---|---|
| **概览** | Box 的 CPU、内存与运行时长，以及详情；Agent 等待回答时显示 **Agent** 卡片 |
| **终端** | Box 内的全部 tmux 会话，每个都标明**你创建**或 **Agent 创建**。见 [终端与会话](terminal-and-sessions.md)。 |
| **文件** | 浏览、上传与下载 Box 卷中的文件，Box 停止时也可以。见 [文件](files.md)。 |
| **端口** | 监听端口，以及你为预览添加的端口。见 [端口预览](port-preview.md)。 |
| **活动** | 近期命令、容器事件和终端会话。其下方**容器输出（docker logs）**显示 Box 日志，带**自动刷新**。 |
| **设置** | Box 的设置，分为七组：**资源**、**存储与挂载**、**工具**、**环境变量**、**生命周期**、**安全**和**检查点**。 |

**资源**一组显示 CPU 与内存限制、当前用量，以及**调整配额**按钮。**生命周期**一组包含启动命令、空闲超时与 TTL。**安全**一组显示网络出站与安全档位。**检查点**一组列出 Box 数据的副本。见[检查点](checkpoints.md)。

标题栏中的**创建检查点**按钮可在任一标签页为 Box 拍摄检查点；标题栏还有**重建**按钮。

## 概览与 Box 列表

**概览** 页是第一个画面，包含两个列表：

- **正在进行** 列出 Agent 正在工作的 Box。见[在概览中观察 Agent](terminal-and-sessions.md#在概览中观察-agent)。
- **需要关注** 列出 MiniBox 记录的问题：Box 内存耗尽、检查点失败、Box 的运行设置与规格不一致、等待你确认或撤销的回滚、超出硬上限的卷、未响应的存储池、离线的宿主机，以及磁盘剩余空间低于下限的宿主机。内存耗尽与检查点失败会保留一天，其他事项在其条件存续期间一直列出。**查看** 会打开显示该问题的 Box 标签页、卷或宿主机设置。

**Box 列表** 中，Agent 正在某个 Box 中工作时，该行会显示 **Agent 活动中 · 12 秒前**。Agent 在最近 10 分钟内在该 Box 中操作过，或它启动的命令仍在运行，即视为正在工作。时间是 Agent 最近一次在该 Box 中操作的时间。

## 启动、停止与重启

使用**启动**、**停止**和**重启**按钮。它们在 Box 列表和 Box 页面顶部。

- **停止**保留 Box 的文件和卷。其进程结束。
- **启动**用相同文件再次运行 Box。
- **重启**先停止再启动 Box。

Box 也可能自行停止。空闲的 Box 可以休眠，带 TTL 的 Box 到期后会停止。见 [空闲休眠与 TTL](idle-sleep.md)。

## 启动命令

启动命令是每次 Box 的容器启动时都会运行的一条 shell 命令。它适合用于需要随 Box 一起恢复的任务，例如开发服务器。

以下情况会运行该命令：创建、启动或从休眠中唤醒、重启、重建，以及从检查点恢复。从模板、快照或检查点创建的 Box 不会获得源 Box 的命令，如有需要，请在新 Box 上另行设置。模板本身不携带启动命令。

要设置命令，打开**设置**标签页中**生命周期**下的**启动命令**卡片，点击**设置命令**或**编辑**，然后点击**保存**。也可以在创建对话框的**高级**中填写。你可以随时更改或移除命令，包括 Box 停止或休眠时，且无需重建。改动在下次启动时生效。Box 运行中时，保存前勾选**现在也运行一次**，新命令会立即运行。**重新运行**会按已保存的命令再运行一次，不会更改命令。

命令的运行方式如下：

- 以用户 `dev` 的身份在 `/workspace` 中运行，使用 `bash -lc` 与 Box 的环境变量。命令按你输入的原样保存。
- 在名为 `minibox-init` 的 tmux 会话中运行。要查看它，请打开 Box 的终端，或通过 SSH 连接，然后运行 `tmux attach -t minibox-init`。按 `Ctrl+B`，再按 `D` 即可分离。
- 不会阻塞启动。MiniBox 最多等待五秒让命令启动，命令失败也不会阻止 Box 启动。

卡片会显示命令的状态：

| 状态 | 含义 |
|---|---|
| **未设置** | Box 没有启动命令。 |
| **等待下次启动** | 已设置命令，但自 Box 上次启动以来尚未运行。 |
| **运行中** | 命令正在运行。 |
| **已退出（代码 N）** | 最近一次运行以退出代码 N 结束。卡片还会显示结束时间与输出的末尾。 |
| **启动失败** | MiniBox 无法启动该命令。卡片会显示原因。 |

若卡片提示最近一次运行使用的是命令的旧版本，请重新运行，以使用当前版本。

命令最长 4096 字节。可以跨多行，也可以包含制表符，但不能包含其他控制字符。

启动命令不会让 Box 保持唤醒。其 `minibox-init` 会话只有在有人 attach 到它时才算使用。使用**重新运行**或**现在也运行一次**再次运行命令，会重新开始空闲计时，与 `exec` 相同。见 [空闲休眠与 TTL](idle-sleep.md)。

读取启动命令需要访问令牌具有 `secret:use` 权限范围。设置、移除或运行命令还需要 `exec`。命令及其输出可能包含密钥，因此活动日志与事件只记录命令已被更改，不记录其内容。见 [访问与令牌](access-and-tokens.md)。

在命令行中：

```bash
minibox box create my-box --startup-command "python3 -m http.server 8000"
minibox box startup-command get my-box
minibox box startup-command set my-box --command "python3 -m http.server 9000" --apply
minibox box startup-command run my-box
minibox box startup-command rm my-box
```

[REST API（英文）](../../reference/api.md) 以及 MCP 工具 `get_startup_command`、`set_startup_command`、`delete_startup_command` 和 `run_startup_command` 提供相同的功能。

## 更改 CPU 与内存

1. 打开 Box，点击**设置**，再点击**资源**。
2. 点击**调整配额**。
3. 设置 CPU 与内存限制，点击**保存**。

若将内存降到低于当前用量，可能失败，或因内存不足终止器而停止 Box。

## 重建 Box

重建会用新容器替换 Box 的容器。在更改模板、环境变量、挂载或安全档位时使用。

1. 打开 Box，在标题栏点击**重建**。
2. 阅读预览。其中列出将发生的更改。
3. 点击**确认重建**。

重建会保留：

- 已挂载的卷及其文件。
- Box 的名称和稳定 ID。
- Box 的版本历史。

重建会丢失：

- 可写层，其中包含在卷外安装的文件，例如通过 `apt install` 安装的。
- 运行中的进程，包括 `tmux` 会话。
- 容器的 IP 地址。

重建前，MiniBox 会先拍摄 Box 数据的[安全检查点](checkpoints.md#安全检查点)。预览中的**重建前先拍摄安全检查点**默认勾选。重建失败时，MiniBox 会恢复 Box 并丢弃该检查点；若无法原样恢复，则保留检查点。

若要保留手动安装的软件，重建前将 Box 存为模板。见 [模板](templates.md)。

## 删除 Box

1. 打开 Box，点击**删除 Box**。
2. 若要移除仅该 Box 使用的卷，勾选**同时删除这个 Box 自有的数据卷**。
3. 点击**删除 Box**。

删除 Box 时，无论是否勾选删除卷，MiniBox 都会把 Box 的 workspace 与 home 数据副本保留在[回收站](checkpoints.md#回收站)中，保留 `TRASH_RETENTION_DAYS` 天，默认 7 天。要恢复该 Box，可在**回收站**页面恢复对应记录，它会作为新 Box 创建。若要删除且不保留副本，请勾选**删除时不保留副本**。只有所有者，或持有 `trash:skip` 权限的令牌可以这样做。

其他 Box 使用的卷，以及你在**存储**的**卷**标签页创建的卷，会保留。删除 Box 不会删除仍被其他 Box 挂载的卷。

## 从命令行使用 Box

列出 Box，请运行：

```bash
minibox box ls
```

在 Box 中运行命令，使用 `minibox exec`：

```bash
minibox exec my-box -- npm test
```

运行 `minibox exec --help` 查看全部选项。见 [CLI 参考（英文）](../../reference/cli.md)。
