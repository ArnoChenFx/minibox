# Agents

`POST /mcp` is a Streamable HTTP MCP server. Send `Authorization: Bearer` with the access key or an agent token. A browser session cookie is refused. `GET /mcp` is not an event stream (`405`, `Allow: POST, DELETE`). `DELETE /mcp` closes the session named by `Mcp-Session-Id`. A wrong Bearer key counts toward the same login limit as a wrong login key, so after 10 failures from one address within 5 minutes the next one gets `429`.

An agent token is held to its scopes. `tools/list` offers it only the tools those scopes reach, and a call it may not make returns a tool error with the code `forbidden` and runs nothing. A session belongs to the principal that opened it, and it ends when that token is revoked.

> **Warning: the main access key grants full owner access over `/mcp`.** Any client that holds the key can call every tool in the toolsets it asks for, including `exec` as root in a box that is not `strict`, `delete_box` and `rebuild_box`. Give an agent an agent token ([#13](https://github.com/ArnoChenFx/minibox/issues/13)) rather than the key. Keep the key out of prompts, logs and repositories, and change `ACCESS_KEY` if it leaks.

`?toolsets=` selects toolsets: `core`, `session`, `network`, `storage`, `tools`, `meta` and `rebuild`. The query wins over the session. The default is `core,meta`. `rebuild_box` is in the `rebuild` toolset, so it is not in the default list: use `/mcp?toolsets=rebuild`, or `/mcp?toolsets=core,meta,rebuild`, to enable it. The design catalog is 27 tools, 15 of them in the default toolsets, and it does not list `rebuild_box`. This server exposes the tools that exist: `list_boxes`, `get_box`, `create_box`, `update_box`, `box_action`, `delete_box`, `exec`, `exec_get`, `exec_kill`, `read_file`, `write_file`, `list_files` and `copy_files` in the default toolsets (13 tools), `rebuild_box` in `rebuild`, `session_start`, `session_send` and `session_read` in `session`, the nine volume and pool tools in `storage` (`list_volumes`, `get_volume`, `create_volume`, `delete_volume`, `attach_volume`, `detach_volume`, `measure_volume`, `list_pools` and `replace_pools`), and `list_tools` / `install_tool` / `upgrade_tool` / `uninstall_tool` / `reconcile_tools` in `tools`. `get_activity` and `task_wait` are not implemented yet. `create_volume`, `delete_volume`, `attach_volume`, `detach_volume` and `replace_pools` need `confirm: true`; without it the call changes nothing and returns `confirmation_required` with `details.preview`. `measure_volume` only refreshes the cached size, so it has no confirm. `network` (list_ports, expose_port) and `meta` are accepted; enable `tools` for Agent CLI install operations (`list_tools`, `install_tool`, `upgrade_tool`, `uninstall_tool`, `reconcile_tools`). File tools `read_file`, `write_file`, `list_files` and `copy_files` are in `core` (volume-scoped; helper + archive API).

`minibox mcp` proxies newline-delimited JSON-RPC from stdio to `/mcp`. Build the binary with `bun run build:cli`.

The `initialize` result includes the block below. [`README.md`](../README.md) includes the same text, so an agent can paste it into `AGENTS.md`.

## MiniBox

Use the MiniBox MCP server (`/mcp`, Bearer access key or agent token) to work inside a box.

- list_boxes or create_box before doing work. exec starts a stopped box, which changes its revision, unless the box's TTL has passed: then exec fails with box_ttl_expired. Read the revision again before an update that sends expectedRevision.
- exec takes argv (no shell) or cmd (via /bin/sh -c). Default user is dev, default directory is /workspace. A strict box allows only dev or 1000 as the user. The box needs /bin/sh, cat, rm and sleep.
- Pass secrets in env, not in argv or cmd. The audit log keeps commands and argv, but never env values.
- The result includes status, exitCode, stdout, stderr, truncated and durationMs. A non-zero exit code is the program's status.
- Inline output keeps about 16 KiB from the start and 16 KiB from the end of each stream. When truncated is true, outputRef names the rest: GET /api/execs/{execId}/output.
- A foreground exec may set timeoutSec up to 55. For a longer command, use exec with background true and a larger timeoutSec (up to 3600), then exec_get with waitMs (max 25000). exec_kill stops the process tree.
- exec can read and write every volume mounted on that box.
- rebuild_box is in the rebuild toolset (`/mcp?toolsets=rebuild`) and needs confirm true.
- session_start, session_send and session_read drive a tmux session in the box. They are in the session toolset (`/mcp?toolsets=core,session`). A session keeps running after you disconnect. Use exec for one-off commands and a session for long-running or interactive programs. Listing and closing sessions are in the REST API and the CLI only.
- A session started through MCP has origin agent. A person can take it over in the console. While they hold it, session_send fails with taken_over and retryable true: wait a little, read the session with session_read, and send again. session_read still works during a takeover.
- session_read returns lines and a cursor. Pass the newest cursor as since to read only what is new. reset true means the screen was redrawn, and lines is the current window.
- session_send takes keys (tmux names such as Enter, Tab, Escape or C-c) or text, but not both. The audit log keeps the counts, never the input.
- The tools toolset (`/mcp?toolsets=tools`) holds list_tools, install_tool, upgrade_tool, uninstall_tool and reconcile_tools. Installs write to the shared tools volume and update BoxSpec.tools. list_custom_tools, put_custom_tool and delete_custom_tool manage the custom catalog in DATA_DIR/tools.d. Only the owner may use them. delete_custom_tool removes the file and does not uninstall the tool.
- The storage toolset (`/mcp?toolsets=storage`) holds the volume and pool tools. create_volume, delete_volume, attach_volume, detach_volume and replace_pools need confirm true. Without it the call changes nothing and returns confirmation_required with details.preview. attach_volume and detach_volume rebuild the box, so the same mount rules apply as to rebuild_box. measure_volume only refreshes the cached size.
- The network toolset (`/mcp?toolsets=network`) holds list_ports and expose_port for path-mode previews under `/box/<name>/<port>/`.
- read_file, write_file, list_files and copy_files act on volumes (not boxes). They work when no box is running, via a helper container and the Docker archive API. A call keeps the boxes that mount the volume awake while it runs, and it never starts a stopped box. Paths are jailed inside the volume. write_file stamps uid/gid 1000 (dev). exec already implies volume RW on mounts of boxes the token may use; files:* only matters without exec.
- The default toolsets are core and meta. The design catalog is 27 tools, 15 of them in the default toolsets; this server exposes the tools that are implemented.

## Exec

`exec` means the caller can read and write every volume mounted on that box. Finer `files:*` scopes only matter for a token that does not have `exec`. Mounting a volume needs `volume:attach` on that volume, and a read-write mount or a new volume also needs `volume:write`. The owner key holds every scope. An agent token holds only the scopes it was created with (#13).

A foreground call may set `timeoutSec` up to 55 seconds, which stays under the server's 60-second idle timeout. Longer commands use `background: true` with a larger `timeoutSec` (up to 3600) and `exec_get`. At most 8 background execs run per box and 64 across MiniBox; a call over either limit gets `429` and does not start a stopped box. A timeout stops the process tree and returns `timedOut: true`, with the exit code from `exec.inspect`, or 137 when the engine does not report one. If the stop fails, the exec stays `running`, a foreground call returns with `timedOut: true`, the stop is retried after a growing delay, and `exec_kill` can retry too.

Stopping a box is not required before `exec`: a stopped box is started, and that changes its revision, so read the revision again before an update that sends `expectedRevision`. A box past its TTL stays stopped: exec returns `409` with `box_ttl_expired` and does not start it (see [Idle sleep](../README.md#idle-sleep)).

Commands and argv are written to the audit log, so pass secrets in `env`, not in `argv` or `cmd`. Under the `strict` profile exec runs only as `dev` or `1000`. Other profiles may run as `root`, and the audit marks those runs `privileged: true`. The `X-Minibox-Client` header does not change the audit source: REST calls are recorded as `rest` and MCP calls as `mcp`.

The box needs `/bin/sh`, `cat`, `rm` and `sleep`: the exec wrapper and the process-tree stop run them inside the box.

Volume file tools (`read_file` / `write_file` / `list_files` / `copy_files`, plus archive upload/download) use a helper container and the Docker archive API, so they work when no box is running.

## Sessions

A session is a named tmux session in the box. Agents drive it with `session_start`, `session_send` and `session_read`, or with `POST /api/boxes/:id/sessions`, and the console opens a terminal on the same sessions. A session runs as `dev` in every profile, including `strict`, and keeps running after you disconnect. It ends when it is closed or the box stops. Use exec for a one-off command, and a session for a long-running program or one that needs input.

- **Origin and controller.** `origin` is `agent` for a session the API or MCP created, and `human` for one the console created. `controller` says who may type now: `agent` or `human`. A session starts under the controller that matches its origin, so a session the console started stays with the person until they return it.
- **Takeover.** In the console, a person can take an agent's session over. Until they return it, `session_send` fails with `taken_over` (409, `retryable: true`), and so does closing the session, because only the console can close a session a person holds. The message names the session. Read it with `session_read`, wait a little, and send again. `session_read` still works during a takeover.
- **What the lock does not cover.** The lock applies to the session API and the terminal, not to `exec`. An agent that runs `exec` in the box as `dev`, the user the tmux server runs as, can still reach the session with `tmux send-keys` or `tmux kill-session`, whoever holds it. A takeover asks agents to stop; it is not a sandbox. `exec` as root is not limited by it either.
- **Return.** The person returns the session with the console's "Return to agent" button. It also returns by itself after `SESSION_TAKEOVER_IDLE_SEC` seconds without their input: 300 by default, and `0` turns this off. With `0`, a takeover lasts until it is returned, even if the page closes. A restart of MiniBox resets every session to the controller its origin implies.
- **Reading.** `session_read` returns `lines` (the end of the screen and its history: 100 by default, at most 2000), `truncated`, `controller` and `cursor`. It looks back at most 4000 lines of history. Pass the newest `cursor` as `since` to get only the lines that are new. `reset: true` means the screen was redrawn, the cursor is not the newest one, or MiniBox restarted. `lines` is then the current window.
- **Sending.** `session_send` takes exactly one of `keys` (tmux key names in order, such as `Enter`, `Tab`, `Escape`, `C-c` or `Up`, at most 32) and `text` (literal UTF-8, at most 16 KiB, where a newline is Enter for the shell). The audit log keeps the number of keys and bytes, never the input.
- **Terminal socket.** `GET /api/boxes/:id/terminal?session=NAME` is a WebSocket that attaches to one session. Only a browser session can type, take over or return it. A Bearer caller reads the output, and its input gets a `forbidden` error frame (`terminal_read_only`). Its tmux client is read-only and ignores the window size, and its `resize` frames are dropped, so it never changes the window size. That attach needs tmux 3.2 or later in the box.
- **Limits.** A box holds at most 16 sessions, and a session has at most 8 terminals open at once, counting one that is starting. Bearer terminals may hold at most 6 of those 8, and the other 2 are kept for the browser console. Past any of these limits the call fails with `too_many_requests` (429) and a hint: close one, then try again. The 16 counts every tmux session in the box, including one made outside MiniBox even when its name is one MiniBox cannot use, such as `my work`. Those sessions are not listed or addressable, but they take a place.
- **REST and CLI only.** Listing and closing are `GET /api/boxes/:id/sessions`, `DELETE /api/boxes/:id/sessions/:name`, `minibox session ls` and `minibox session close`. A stopped box lists no sessions.
- **Errors.** `not_found` (404) means the session does not exist, or the box is stopped, and the hint says how to start it. `conflict` (409) with the key `session_image_unsupported` means the box's image cannot run sessions: it is too old, or it lacks tmux or the `dev` user. Build the base template again, then rebuild the box onto it. A Bearer terminal on a tmux older than 3.2 gets a `conflict` (409) as well, with a hint to rebuild from the base template. Boxes from the base template include a tmux new enough for both. `taken_over` (409, `retryable: true`) means a person holds the session. `too_many_requests` (429) means a limit in this section was reached.

## Checkpoints

Checkpoints are REST only. There are no MCP tools for them yet, so an agent on `/mcp` cannot take, fork or roll one back. Use `POST /api/boxes/:id/checkpoints`, `POST /api/checkpoints/:id/fork` and `POST /api/boxes/:id/rollback` with an agent token. Each returns `202` with a `taskId`, and the result is on the task.

- **Scopes.** `checkpoint:create` takes a checkpoint, and changes or deletes the ones the token created. `checkpoint:restore` rolls a box back. Forking needs `box:write`. Listing and reading need one of `box:read`, `checkpoint:create` or `checkpoint:restore`.
- **Consistency.** `live` (the default) reads the volumes while the box runs, so the copy is crash-consistent. Use `pause` when the files must not change during the copy: it freezes the box's processes until the copy is done. `stop` stops the box and starts it again afterwards, which changes its revision twice, so read the revision again before the next `If-Match` request.
- **Rollback.** Send `If-Match` with the box's current revision. Without `"confirm": true` the call changes nothing and returns `409 confirmation_required` with `details.preview`, which lists the volumes it would replace. With `confirm: true` the box is rebuilt onto new volumes, and the replaced volumes are kept. Delete them with `DELETE /api/volumes/:id?confirm=true` once they are no longer needed.
- **Sleep.** A checkpoint, fork or rollback keeps the box awake while it runs, so idle sleep does not interrupt it. None of them wakes a box that is asleep. A rollback leaves a sleeping box asleep, though the rebuild starts the container briefly first.
- **Trying a change.** A fork creates a new box with new volumes and leaves the source box alone. `copyHome` is `false` by default, so the new box starts with an empty home.
